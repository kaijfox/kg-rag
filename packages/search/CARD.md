# @kg/search (WP8, Haiku)

Contract: `@kg/core` CONTRACT_VERSION 0.6.1. You need this card, `core`, `@kg/pipeline` (its README and `src`),
`testkit`, and `.claude/skills/xstate/SKILL.md` (XState v5 only); nothing else.

A search is a state machine. v0 has exactly one search machine, `similarity` (retrieve, then cut). The package holds the
search service, the machine, the two step implementations the machine calls, and the machine's pin and diagram.

## Implements (core `ports/search.ts`)
- `createSearch(d: { store: CorpusStore; embedder: Embedder; llm?: Llm }): SearchService`.
- Typed step constructors (plain functions, no registry, no `JsonObject` parameters):
  `vectorKnn(p: { pool: number; kinds: ItemKind[]; into?: string }): SearchStep` and `truncate(p: { k?: number }): SearchStep`.
- `similarity`: the XState machine, `similarityRecipe(settings?)`: builds a core `SearchRecipeSpec`, `similaritySettingsSchema` (strict zod),
  `SIMILARITY_VERSION = '1'`, and a small registry `searchMachines` keyed by `machine@version`
  (`{ name, version, machine, parseSettings, topology }`). Only `similarity@1` exists.
- `machines/pins.json`: `{ "similarity@1": { "topology": "<16 hex>" } }` and `docs/similarity.mmd`, the Mermaid diagram
  generated by `toMermaid(machineMapOf(similarity, ...))`.

## Service (plain function: `src/service.ts`)
1. build = `req.buildId ?? store.currentBuild()` (none -> `precondition`; unknown -> `not_found`); recipe id =
   `req.searchRecipeId ?? build.manifest.searchRecipeId` (recipe must be kind `search`, else `not_found`);
   space = `build.manifest.embeddingSpaces[0]`; refuse (`precondition`) if the embedder does not serve it.
2. Look up `recipe.spec.machine` at `recipe.version` in the registry: unknown -> `invalid_input` (`unknown search machine X@V`);
   `recipe.spec.topology` differs from the registered topology -> `invalid_input` (`machine X@V no longer has the topology this recipe was made for`);
   settings fail the strict schema -> `invalid_input`.
3. `searchId = ctx.ids.ulid('sr_')`; tag `{ searchId, buildId }`; emit `query` with the tag; run the machine with
   `runPipeline` (identity: pipeline `search`, machine, version, topology, recipe id). Event order of a search:
   `query`, `pipeline.started`, N x `search.step`, `pipeline.finished`, `search.result`.
4. Initial state: one query variant `{id:'q0', text: query, origin:'original', parentId:null}`, empty candidates, seeds `[]`,
   `pools:{}`, `notes:{}`. Final = `sortCandidates(candidates).slice(0, k)`, texts from `store.getItems`, `stale =
   store.staleCheck(buildId).stale`; emit `search.result`; return `{ searchId, buildId, stale, items }`.
   A failed run: `runPipeline` emits `pipeline.finished` with status `failed` and rethrows the `KgError` (becomes `tool.failed`).

## The machine (`src/machines/similarity.ts`, with `src/machines/kit.ts`)
Use exactly this shape (adapt only what the compiler forces). `stepActor` is the single place that emits `search.step`:
```ts
// kit.ts
import { fromPromise } from '@kg/pipeline';
import type { BuildId, Ctx, SearchId, SearchState, SearchStep, StepEnv } from '@kg/core';
export interface SearchRun { env: StepEnv; ctx: Ctx; tag: { searchId: SearchId; buildId: BuildId }; nextIndex: number }
export interface StepInput<P> { run: SearchRun; at: string; state: SearchState; params: P }
export function stepActor<P>(make: (p: P) => SearchStep) {
  return fromPromise(async ({ input }: { input: StepInput<P> }): Promise<SearchState> => {
    const step = make(input.params);
    const t0 = input.run.ctx.clock.monotonicMs();
    const out = await step.run(input.state, input.run.env);
    input.run.ctx.emit('search.step', { trace: { ...out.trace, state: input.at, stepIndex: input.run.nextIndex++,
      durationMs: Math.max(0, input.run.ctx.clock.monotonicMs() - t0) } }, input.run.tag);
    return out.state;
  });
}
```
```ts
// similarity.ts: states retrieve -> cut -> done, with failed; every work state's onError goes to #failed keeping the error
import { setup, assign, toKgError } from '@kg/pipeline';
export const similarity = setup({
  types: { context: {} as Ctx, input: {} as In, output: {} as SearchState },
  actors: { retrieve: stepActor(vectorKnn), cut: stepActor(truncate) },
}).createMachine({
  id: 'similarity', context: ({ input }) => input, initial: 'retrieve', output: ({ context }) => context.state,
  states: {
    retrieve: { meta: { logs: 'search.step', step: 'vector-knn', label: 'find similar passages' },
      invoke: { src: 'retrieve',
        input: ({ context }) => ({ run: context.run, at: 'retrieve', state: context.state, params: { pool: context.settings.pool, kinds: context.settings.kinds } }),
        onDone: { target: 'cut', actions: assign({ state: ({ event }) => event.output }) },
        onError: { target: '#failed', actions: assign({ error: ({ event }) => toKgError(event.error) }) } } },
    cut: { /* same shape: actor 'cut', at 'cut', params {} , meta { logs: 'search.step', step: 'truncate', label: 'keep the top k' }, onDone -> 'done' */ },
    done: { type: 'final' },
    failed: { id: 'failed', type: 'final' },
  },
});
```
Rules for machine files: build with `setup()`; no bare `fromPromise` in a file under `machines/` (use `stepActor`); no `search.step`
emit outside `stepActor`; no import of `xstate` (only `@kg/pipeline`).

## Steps (`src/steps/`)
Never mutate the input state; return candidates sorted by core `sortCandidates`, unique per item; `considered` always
contains every input candidate (the previous step's output). Retrieval steps MERGE: output = `fuseMax(existing candidates + retrieved)`, so re-running one on its own
output changes nothing. `vectorKnn` embeds every `state.queries` entry (one embed call, `renderQuery`), runs knn per variant, tags candidates
with `queryId` (copied into every `RankedRef`), fuses with the existing candidates, logs `considered` = all fused (no cut: each variant contributes at most
`pool`), `output` = the same list, and `queries`. Candidates carry the item's `sourceChunkIds` (Rule 1). Named pools (full text in core `ports/search.ts`):
`vectorKnn` with `into: "<name>"` merges the hits (fuseMax with the existing pool) into `state.pools[name]` and leaves `candidates` untouched (output = input
candidates; `considered` = input candidates); `{queryId}` in the name expands per variant; without the placeholder all variants fuse by max into the one
pool; the step sets `trace.pools` for the pools it wrote; every other step passes `state.pools` through unchanged. The `fuse` step is specified in core
but NOT built in v0: do not implement it. `truncate` keeps the top `k` (default the request's k) by `sortCandidates` and logs `considered` = input, `output` = the kept.
The `state` field of the trace is added by `stepActor`; the step's own trace omits it.

## Pins and the diagram
- `machines/pins.json` holds the topology (`topologyOf(similarity)`, 16 hex). A test recomputes it and fails on drift; a second test regenerates the Mermaid
  diagram from the machine and fails if `docs/similarity.mmd` differs.
- Core's `DEFAULT_SEARCH_RECIPE.spec.topology` is a literal that must equal the machine's topology. You are allowed ONE edit outside your package: replace
  that literal in `packages/core/src/defaults.ts` with the real value, then regenerate the golden vectors (`cd packages/testkit/golden && python3 -I oracle.py`, the
  oracle reads the literal; check `oracle.py` for where the topology is written and update it too), and run `pnpm --filter @kg/core test` and
  `pnpm --filter @kg/testkit test`. Report the old and new values and the changed golden ids in your notes. A test in your package asserts
  `similarity` topology equals `DEFAULT_SEARCH_RECIPE.spec.topology`.
- A change to the machine's states, moves, guard names or step names changes the topology; a behaviour change that keeps it (a guard body, a step) needs a
  version bump and a new golden run.

## Decisions already made
Hand-written machine per pipeline, recipe = machine name + version + settings + topology; 100-candidate trace pool per variant; merge-on-retrieve; score and tie rules in core;
`queries`, `seeds`, `notes` and named pools reserved for later machines; stale flag on every response. Future search machines (decomposition, critique loops) are not built.
