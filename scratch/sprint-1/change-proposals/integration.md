# Change proposals from the integration run (stat-mech corpus, real SQLite, Ollama)

1. **A failed pipeline does not record the state that failed** (`packages/pipeline/src/run.ts:50-61`). `pipeline.finished` carries `state`, which is the final state (`failed`), not the work state that threw. Evidence: search with the embedder unreachable logs `pipeline.finished {status:"failed", state:"failed", error:{code:"upstream",...}}`; the log shows only the absence of `search.step` for `retrieve`. The viewer README says the diagram marks the failed state as the stop, but it cannot (screenshot: every node grey, only `failed` lit). Fix: keep the last entered non-final state (the machine's previous state value) and write it as `failedState` or in `state`. Severity: medium (diagnosis).
2. **Question generation drops drafts silently and logs nothing** (`packages/eval/src/prompts/generate.ts:84-103`, `machines/evalGenerate.ts`). 8 groups gave 6 questions, 10 groups gave 6. No event, no count, no reason (parse failure, duplicate, wording copy). The set's `genRecipeId` is null, and the generation LLM calls are not logged. Fix: return `{drafts, dropped:[{group, reason}]}` and let the caller log it; record the generation recipe id with the set. Severity: medium.
3. **Judge accepts an answer that ignores the context** (judge prompt `packages/eval/src/prompts/judge.md`). Gold-condition answer for q2 began "Based on my own knowledge" and scored 1.0; 12 of 12 answers scored 1 in the first run (retrieved and gold), and `no-context` still scored 0.75 on 6 questions that are answerable from general knowledge. Not a package defect on its own; the judge validation is still pending, so no number is trusted. Severity: low until the validation runs.
4. **Generated questions can depend on their passage** (`generate-single-hop.md`). Examples: "What specific problem does kinetic theory aim to solve regarding systems of moving particles?", "Why did Gibbs introduce the factor involving N! in equation (2.10)?". The second names an equation number only the passage gives. Severity: low (eval design review).
5. **`@kg/viewer` ships a JavaScript module without declarations** (`packages/viewer/src/index.ts:6`). Any consumer (app) fails typecheck with TS7016 unless it sets `allowJs`. Fix: add `web/render.d.ts` or write the re-export types by hand. Severity: low.
6. **Viewer page behaviour** (`packages/viewer/web/app.js`). (a) Changing only the URL hash on an open page does not switch the session. (b) The run picker keeps the run that was selected; on a live session a new search is not followed. (c) The item text panel stays when another session is selected and covers the timeline. (d) The session list reorders when any session gets an event, so a click can land on a different session than the one under the cursor (happened twice during the live test). (e) The header count ("16 events") lags the list. Severity: low to medium (d).
7. **MCP `search` requires `k`** (`packages/core/src/schemas.ts:89`). An agent that omits it gets `invalid_input: ... k: Invalid input: expected number, received undefined`. A default of 10 would match what agents send. Severity: low.
8. **`eventsBySearch` omits `tool.failed`/`tool.returned`** (they carry no `searchId`; only `parent_id` ties them). For a failed search the reader's per-search view ends at `pipeline.finished`; the tool-level error needs the session view. Severity: low.
9. **`query` event records no embedder** (`packages/search/src/service.ts` `ctx.emit('query', ...)`). Model and digest are derivable from the build's space, so this is acceptable, but a search run with a different embedder under the same space name is not distinguishable. Severity: low.
