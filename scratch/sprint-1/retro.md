# Sprint 1 retro (2026-10-18)

State: 16 packages, 903 tests passing (plus 24 in the sidecar), depcruise clean, a real run on the stat-mech corpus (312 chunks, search median 29 ms). Reviews found no blocker and 15 should-fix items. No eval number is trustworthy yet.

## Standing questions

**Where did cheap models need sibling code or contract changes?** Agents filed 39 change proposals. Most were not model errors. They came from conformance suites and cards that disagreed with each other after contract 0.5.0 rewrote the pipelines: ingest and eval could not satisfy `machineMapConformance` ("work states must log") with their own card's states, `machineLogConformance` was search-only, the eval runner suite fixed event indices that a pipeline bracket breaks, and the testkit search recipe named an unregistered machine version (8 failing cases). The 0.5.0 wave left testkit at a minimum (`wave1-todo.md`). Sibling code: the notes record no agent reading another package, and 17 ingest scenarios and 11 api paths matched the hidden skeleton exactly.

**Which models handled which packages well?** The notes do not record which model built which package (a process gap); the cards assigned a Sonnet/Haiku split. By outcome only: store (Sonnet) was the strongest package (a real fake-versus-SQLite cross-check, trigger tests, 3 mutation survivors of 23). embed, parse, mcp and api needed nits only. chunk, the most consequential, matched the skeleton on all real slices but was wrong on two boundary rules (116 of 2000 and 313 of 2000 random blocks cut differently) and on inline formulas, and its tests left about 16 of 28 mutants alive. eventlog lost events across processes (4 processes by 300 appends: 57 to 300 succeeded) because a deferred transaction is the wrong default; a probe found it, no test did. eval (judge and prompts) had the most should-fix items: unlogged judge calls, no judge/answerer recipe in the run, a retry that resent the identical cached request. viewer shipped two security gaps. Pattern: cheap models followed cards literally and missed what cards did not say (concurrency, boundaries, security).

**What did integration surface that package tests could not?** The failing search state was lost in the log; question generation silently dropped 25 to 40 percent of groups; the viewer list reordered under live updates; the log costs 28 KB per search; the judge scored 1.0 on an answer that began "Based on my own knowledge". Concurrent processes on one WAL file gave no lock errors. The sidecar and decoding paths were not exercised.

**Is v0 a sound base for the relation layer?** For chunks, builds, ids and the log, yes: Rules 1, 5 and 6 audited at zero violations on 312 chunks. But the Rule 1 and 4 audits were vacuous for derived items because none exist. Unproven: writing derived items (summaries have no storage, `derivedItemId` throws, relation node order depends on rowid and a `position` column is only proposed), nondeterministic producer identity (AM-7), and a log that will grow with every added step. Needed first: delta-encode `considered`, add `position`, decide item identity.

## Sprint questions

**Did the lifecycle document and invariants catch anything package tests did not?** Yes, twice. Writing section 4 exposed that the old document version appeared in no event, which led to `previousDocVersionId` and `build.created.revert` in 0.4.0. And its "no test yet" list (Q-9 pool size, I-11 duplicate docKey, I-12 pointer order, I-7 beyond embedder failure) predicted survivors that mutation testing later found in search and ingest: the `pool+1` mutant, the duplicate docKey guard, the disabled gate. The mistake is that the list was not turned into tests before the packages were built; it stayed a document. It was written against 0.2.0 and is stale.

**Did the state-machine decision hold up once applied?** Mechanically yes: every pipeline is a machine, the viewer draws the logged path in a real browser, nothing was rebuilt. Costs: 104 lines against 15 for search; "work state must log" forced a routing-state workaround in three packages; `topologyOf` ignores step parameters and guard bodies yet changes with cosmetic labels, so a rename moves every build id. The reason for machines (loops, decomposition) has no v0 consumer, so that benefit is untested. The user overrode the spike's own pre-set rule.

**What did mutation testing and the oracle diff find that suites did not?** Mutation: about 65 of 203 mutants survived (32 percent; Sprint 0 was 13 of 38, 34 percent), concentrated in boundary comparisons (chunk packing, retrieval cut, eval k+1). The suites pinned behaviour but not edges. Oracle diff: 13 divergences from the skeleton, 3 where the skeleton was right (both chunk splitting rules and the recorded k), 5 where the package was right (stricter checks), 3 package bugs (inline formula render throw, optional `chunkView`, wrong block refs in extras) and 2 ambiguous. Golden vectors and conformance passed all of them. The diff checks the spec, mutation checks the tests.
