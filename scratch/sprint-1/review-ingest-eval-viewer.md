## Should-fix

1. **Judge LLM calls are never logged** (`eval/src/machines/evalQuestion.ts` judgeActor, `prompts/judge.ts` makeJudge). `RunDeps.judge(q, answer, cond)` takes no ctx and `makeJudge(llm)` wraps a bare `Llm`; only the answerer goes through `loggedLlm(ctx)`. The `judging` node declares `llm.called` but nothing emits it (the declared-logs test only checks emitted is a subset of declared). Rule 6 / logging gap: no request hash for the judge prompt. Fix: `judge: (llm: Llm, q, answer, cond)` or `(ctx, ...)`, runner passes `loggedLlm(judgeLlm, ctx)`; testkit `RunEval` type and `evalRunner.ts` follow; add a test that `llm.called` with purpose `eval-judge` count equals results.
2. **No recipe for the answerer or judge is recorded with a run** (`runner/run.ts:putRun`, `config` = conditions, ks, searchRecipes). `judgeRecipe()` and `ANSWER_SETTINGS` exist but are used nowhere in the run; `eval.run.started` has no judge/answer recipe id or prompt digest. Rule 4: scores are derived items with no recipe. Fix: put `recipeId(judgeRecipe())`, answer model/settings and an answer prompt digest into `config` and the event (core payload field; lead decision), or at least `config`.
3. **Retry repeats the identical request** (`machines/judge.ts`, `evalGenerate.ts`). Judge uses temperature 0 and the card requires `ReplayLlm`: the retry returns the same (cached) malformed reply, so the budget buys nothing. Fix: on retry append the previous reply plus "Reply with the JSON object only", or vary a `retry` field that enters the request hash.
4. **Viewer accepts cross-site requests and any Host** (`viewer/src/server.ts`). Probe: `POST /api/notes` with `content-type: text/plain`, `Origin: http://evil.example.com` returns 201 (browsers send this without preflight), and `GET` with `Host: attacker.test` works, so DNS rebinding can read the whole log and chunk text. Fix: reject unless `Host` is `127.0.0.1:<port>`/`localhost:<port>`, require `application/json` and no foreign `Origin` on POST; add `Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:` and `X-Content-Type-Options: nosniff`.
5. **Numeric payload fields are interpolated unescaped** (`viewer/web/render.js`: `p.k`, `e.seq`, `r.rank`, `t.stepIndex`, `p.stats.pages`, `chunkCount/inserted/reused/dropped`, `embedded/skipped`, `itemCount`, token counts, `p.overall`, `p.success`). Payloads through the render functions: every string field is escaped (checked ~20 types, including `<img onerror>` in item labels, queries, errors, unknown events); a string in a numeric field renders raw HTML (probe `k: '<img src=x onerror=alert(1)>'`). Only exploitable if a log row bypasses validation (imported jsonl, hand-edited DB), so defence in depth: one `n(x)` helper (`Number.isFinite(x) ? x : escapeHtml(x)`), and a test feeding strings to every numeric field.
6. **Ingest `chunkView` is optional** (`ingest/src/deps.ts`); the card signature requires it. Forgetting to wire it silently embeds raw text under any `formulaView`. Mutant "chunkView never applied" survives. Make it required (testkit edit below).
7. **Ingest recipes and space are written before the precondition check** (`service.ts:ensureConfig`, then the `spaceMismatch` guard). A refused ingest (wrong embedder) has already written recipes/space; harmless (insert-only) but contradicts "failure leaves no partial state", and a throw in `ensureConfig` happens outside the pipeline bracket (no `pipeline.finished`). Fix: check the embedder against `config.space` first in the service, then write; or accept and document.

## Nits
- Eval prompt digest hashes every `.md` including README and the other prompts (`prompts/loader.ts`): editing `answer.md` changes the judge recipe id. Hash only the files a machine uses.
- Judge reply order: score first, rationale after, so the rationale cannot inform the score; with a weak model put `rationale` first (parser is order-free). `maxTokens: 200` is tight if qwen3.5 emits reasoning text. Parser rejects code fences and string scores (`"1"`); a retry (see 3) is then the only recovery.
- Generation prompts: `type` must be echoed and is checked, so a harmless mismatch costs a retry; the type is known, ignore the echo. Example `"uses": [0, 2]` / `[0, 1, 3]` invites copying and out-of-range numbers for small groups. Single-hop says "this passage alone answers" but nothing checks that no other chunk answers it (gold uniqueness); `uses` for multi-hop/topic is the model's claim, unverified (needs the answerability / removal check in Wave 3). `topic` minimum is `min(3, passages)`, so a 1-passage "topic" question is accepted, against the prompt text. Dropped drafts (dedupe, wording) are silent: count them.
- Judge sees answers inside unfenced prompt text; an answer containing "Reference answer:" or "Score: 1" can confuse a weak model (plan covers one such row).
- Duplicate names in `conditions` are not rejected; the second `putResult` conflicts if the answer differs.
- Viewer: malformed `%` escape in `/api/search/...` or `/api/items/...` returns 500 (should be 400); `intParam` fine; Mermaid is configured `securityLevel: 'strict'` (app.js, last lines) but `$('diagram').innerHTML = svg` and the strict behaviour were not exercised in a browser here; `no-store` on a 5 MB bundle.
- Ingest embeds when chunker emits duplicate chunk ids: not guarded (unlikely).

## Checks that passed
- Idempotent re-ingest: `unchanged` from `previous.id === version.id`, build id reused, `buildChanged` false, nothing embedded (mutants on all of it killed). Chunk ids come from the chunker unchanged. Rule 5: `commitIngest` composes from `currentDocVersions()`, consistent with the amendment. Failures: one `store.transaction` (dv, vectors, pointers, build); only artifacts survive a failure, as the card says. Events: started, parsed, chunked, embedded per doc, then extras, then after commit completed per doc and `build.created`, inside the pipeline bracket.
- Moving recipe writes out of the machine (proposal 1) is acceptable for ingest: they are insert-only, content-addressed, and the machine keeps `preparing` as the embedder check. Fix 7 first.
- eval: recall is per unique gold chunk, summaries skipped, empty gold throws; three conditions plus `oracle-gold-first` and per-condition search recipes; retry budget N means N+1 calls, matching the card (killed when off by one); prompt digest is in `judgeRecipe`/`generateRecipe` and pinned.
- Viewer: only `POST /api/notes` writes (other verbs 405); static files come from a fixed table, so traversal probes (`/../`, `%2e%2e`, `//etc/passwd`, `/web/app.js`, `/vendor/..`) all 404; listens on 127.0.0.1 when given a port (the caller owns listening otherwise: say so in the card). Vendored Mermaid: sha256 matches README and equals `npm pack mermaid@12.1.0` byte for byte; 12.1.0 was published 2026-10-02 and is the newest release older than two weeks (12.2.0 is 2026-10-13). Mermaid text: labels pass `clean()` (strips quotes, `#:;{}`, collapses newlines), node ids are `n<i>`, so map text cannot add directives.
